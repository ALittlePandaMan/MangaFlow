## 修复与改进

- 网页和 MCP 地址跟随实际部署端口；设置页、安装说明、HTTP 与 stdio 配置使用一致地址。
- Docker 网页端口使用 `MANGAFLOW_WEB_PORT`，后端对外端口使用 `MANGAFLOW_API_PORT`；源码开发另用 `MANGAFLOW_DEV_PORT`。Compose 尊重显式 CORS 配置，代理保留完整 Host。
- 开发启动器保留热重载，后端服务子进程启动失败时会退出并清理前端；停止时限时清理进程。
- MCP 远程地址拒绝非法主机、端口、凭据及控制字符，错误输入返回 422 并保留原配置。
- 本地连接程序更新到 **2.1.1**；安装器和连接程序要求显式服务地址，地址缺失时提示配置。
- 同步 README、Agent 开发指引与端口、代理、发布包回归检查。

## 从 0.1.2 升级

1. 备份 PostgreSQL 数据库、`data/`、`.env`、`config.yaml` 及密钥。
2. 下载本 Release 的 `mangaflow-docker-0.1.3.zip`，将其中的 `docker-compose.yml` 和 `scripts/` 合并到**原部署目录**。保留原私有配置、数据、模型目录和数据库卷。
3. 在原 `.env` 设置 `MANGAFLOW_IMAGE_TAG=0.1.3`；按需添加 `MANGAFLOW_WEB_PORT`（默认 `8080`）、`MANGAFLOW_API_PORT`（默认 `8000`）。
4. 在原目录执行：

   ```bash
   bash scripts/docker.sh pull
   bash scripts/docker.sh up -d
   bash scripts/docker.sh ps
   ```

端口变量从 0.1.3 开始支持，旧 Compose 仍写死端口，因此本次需同时更新部署文件与应用镜像。不要在新目录重新初始化代替升级，也不要删除原数据库卷。

部署地址变化后，从“设置 → MCP”复制实际安装说明地址，重新运行官方安装器更新连接程序及客户端配置，再重新连接。连接程序使用 `MANGAFLOW_MCP_URL`，安装器支持 `--url` 或该环境变量，命令行优先；不再猜测固定端口。
