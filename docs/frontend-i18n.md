# 界面语言

在“设置 → 界面语言”的下拉框中选择简体中文、繁体中文、英语或日语；顶栏不再提供语言切换入口。首次打开优先使用浏览器支持的语言，之后记住 `mangaflow.locale`；浏览器禁止本地存储时仍可在当前会话中切换。语言偏好只保存在浏览器，不会修改项目的原文／译文语言、API 配置或漫画内容。

## 添加界面文案

- 使用 `src/i18n` 的 `t('简体中文原文')`，变量通过 `t('第 {{v0}} 页', {v0: number})` 传入。不要把项目标题、原文、译文或模型标识当作翻译键。
- 组件调用 `useLocale()` 订阅语言变更。不要通过更改 React `key` 或重新加载页面实现切换，否则会丢失未保存的表单。
- 在 `src/i18n/locales/{en,ja,zh-TW}.json` 中同步添加键。简体中文直接使用源文案。保留所有插值占位符；英文数量可使用 i18next 的 `_one`／`_other` 规则。
- 模块级静态导航保留稳定的对象引用，通过叶子属性 getter 获取当前语言文案。不要把 API 方法、数组或整个数据对象改成 getter。
- CSS 使用 class／data 属性定位，不要依赖已翻译的 `aria-label` 内容。长标签允许换行，图标和操作按钮保持原有尺寸；新增布局在 320、390、768 和 1440px 下检查。
- 服务端返回的未知错误和用户输入保持原样，已知状态使用字典映射。品牌、模型标识和字体预览样本文字保持原样。

## 验证

在 `frontend` 目录运行：

```sh
npm run i18n:check
npm test
npm run build
```

检查脚本验证静态翻译调用的资源覆盖；测试验证四种语言、偏好保存、跨标签同步、键盘操作、插值、资源占位符及切换时草稿保留。界面验收还应检查设置菜单、下拉选项、弹窗、加载状态与编辑器工具栏，避免英文长文案导致横向滚动。
