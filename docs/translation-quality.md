# 漫画翻译质量与安全边界

这轮改进分别处理文字像素、气泡归属、背景修复、阅读顺序、翻译上下文和译文排版。检测矩形仅用来定位，不等于需要擦掉的范围。模型输出仍可能误判，不承诺任意漫画都能零人工修正。

## 去字与复核

1. RF-DETR 一次输出文字、拟声词、气泡和分镜实例，保留各自的几何信息。文字与气泡按真实字形 mask 包含关系关联；归属关系不等于合并所有气泡内文本。重复框由当前共享的完整字形/包含证据处理，不再走旧的气泡拆分和几何合并链路；证据不足的独立区域保留供核对。
2. 使用原文字行 polygon、颜色/连通域证据和可选的 Comic Text Detector（CTD）像素概率图生成字形蒙版。整页缩放后较小的文本增加最多 6 个、最长边 512 像素的原图裁剪放大推理，邻近框共用裁剪；局部证据只补入已定位的小字范围，仍经过原有气泡/轮廓保护。CTD 要有框内强种子才能接纳邻接的弱笔画，不能独立授权擦除整块矩形。
3. 可靠气泡归属会把蒙版限制在真实气泡内，并保护深色轮廓。整页文字区域共同参与背景取样排除，避免相邻文字污染背景色。纯色气泡/严格验证的纸白背景采用确定性填色；纹理和其他区域交给当前修复 Provider（推荐 LaMa）。冲突的颜色或复杂区域重叠优先使用模型。
4. 修复后在原文字行 polygon、既有蒙版及邻近 4 像素内检查残留。全页候选再经过最多 6 个高分辨率裁剪复核；初次与重试固定使用同一组窗口，避免更换裁剪导致分数不可比。局部与整页不一致或未被裁剪预算覆盖的候选标为不确定，而不是通过。蒙版外确认的候选只提示复核，不自动扩大擦除范围。
5. 只有原蒙版内、经局部确认且自动蒙版指纹仍匹配的残留，才最多尝试一次修复。总疑似残留至少减少 20% 且至少 3 像素、各区域不退化，并通过连续线条保护检查后，才能替换第一次净图。线条检查保护从蒙版外延伸进来的长边缘，并非所有纹理的完整质量评估。失败或证据不足均保留原结果。人工蒙版以及生成后被编辑的蒙版不会自动重试。所有检查和重试均在本地执行，不调用云端。
6. 纯纸白判断会排除已确认长边线周围 4 像素的抗锯齿/阴影取样污染，但不扩大擦除蒙版。仍要求足够样本、内外底色一致和严格颜色离散阈值；网点或渐变不据此改为纯色填充。

“通过”只表示模型未在检查范围中发现残留，不代表人工验收通过。检测框以外完全漏检的文字、贴住轮廓的笔画、复杂拟声词、网点与画面纹理仍可能需要人工处理。不要通过无限膨胀蒙版来追求零残留，那会损坏原画。

所有自动蒙版（包括手动创建或调整过的文本框）都先尝试字形分割：使用 CTD 像素结果和可靠的局部颜色证据，不再因为背景均匀、框较大或疑似艺术字而直接整框填充。只有两类证据都失效时才使用 `segmentation_fallback_polygon`，并记录 `fallback_reason`；回退仍遵守当前文本框及气泡轮廓保护。手动涂画、擦除过的蒙版不参与自动重新生成。

## 可选像素模型的安装与来源

本机已缓存约 95 MB 的 CTD ONNX 权重。新环境不会在处理页面时偷偷下载；模型不存在时回退到几何/颜色方案。

- 模型项目：[dmMaze/comic-text-detector](https://github.com/dmMaze/comic-text-detector)，该上游代码仓库标注 GPL-3.0。
- 权重：[manga-image-translator beta-0.2.1 发布附件](https://github.com/zyddnys/manga-image-translator/releases/download/beta-0.2.1/comictextdetector.pt.onnx)。权重作为独立文件获取，不随本仓库提交。上游代码的许可证不自动等于权重和训练数据的完整授权；再分发或商业使用前应核对相应权利。
- 当前适配器独立实现 OpenCV DNN 推理，没有复制上游 Python 实现。
- 文件：`models/text-segmentation/comictextdetector.pt.onnx`，94,669,756 字节。
- SHA-256：`1a86ace74961413cbd650002e7bb4dcec4980ffa21b2f19b86933372071d718f`。

在安装了后端依赖的环境，从仓库根目录执行：

```bash
PYTHONPATH=backend python scripts/install_text_segmentation.py --download
```

Windows PowerShell 用 `$env:PYTHONPATH="backend"` 设置路径后执行相同的 Python 命令。省略 `--download` 仅校验现有文件；下载到临时文件并核对大小及摘要后才替换目标。Docker 使用宿主机挂载的 `models/`。

默认配置：

```dotenv
MANGAFLOW_TEXT_SEGMENTATION_ENABLED=true
MANGAFLOW_REPAIR_AUTO_RETRY=true
```

第一项关闭像素推理及复核，第二项仅关闭二次处理、保留残留检查。概率图按图片内容和模型版本缓存到 `data/cache/text-segmentation/`；这是可重建缓存，不是原图。新算法只作用于后续生成的蒙版，已有项目需执行重新修复来更新结果。

## 阅读顺序与翻译上下文

- 单框、多选和整页翻译会先检查本次待翻译区域的原文：空白原文自动调用默认 OCR Provider 一次，再翻译识别结果；已有原文不重识别，不重新检测或调整框的位置。若同一任务已经执行过 OCR，不会因结果为空而重复识别。识别后仍为空的区域跳过翻译并标记复核；OCR 失败则报告错误，不继续发送空内容。自动 OCR 与翻译属于同一次可撤销操作。
- 有可靠完整边框的分镜先按日漫的从右到左、从上到下顺序分组，再排分镜内文本。边框缺失、候选太少、归属不够明确时沿用原几何排序，不强行猜测分镜。
- 翻译仍按页面批量请求，固定返回所请求的区域 ID。上下文增加区域顺序、坐标、气泡和分镜归属，以及同项目上一页的已识别原文/已有译文。当前页上下文最多 12,000 字符，上一页最多 4,000 字符；不是无限制全书历史。
- 可选整页图像输入已支持 OpenAI Chat Completions、Responses 和 Anthropic Messages 格式。翻译 Provider 的 `config.include_page_image: true` 才启用，默认关闭；模型必须支持视觉输入。图片最长边 1536，重新编码为 JPEG 并剥离元数据。它会向配置的服务商上传整页画面，并增加图像费用。当前没有新增界面开关，可通过模型配置 API 的 `config` 字段显式设置，更新时保留其他配置字段。
- 上下文和图片文字是参考资料，不是指令；不会根据上下文新增、合并或重编号译文 ID。未启用图片输入时不会把内部图片 Data URL 塞进文本提示。
- MangaOCR 的兼容分数字段不再被当作真实置信度。无效字符与异常长重复会触发复核提示，不会擅自修改原文。

## 排版保护

可见译文框是字号和排版范围的唯一依据，不再用气泡分割结果生成隐藏的缩小框。自动字号按实际字形像素适配，预留描边边距；无法容纳时提示溢出。手工指定字号、旋转和透视保留；切换锁定不改变排版。横排对齐只计算一次，避免右对齐文字被裁掉。此实现不是逐行随气泡轮廓排版，极窄或强凹形气泡可能需要手动调整译文框。

画布始终按当前视口分辨率绘制文字，不再因首次编辑而从整页文字 PNG 切换渲染路径，避免小字先糊后清晰。透视文字使用有像素预算的高分辨率局部图块，字体加载会更新预览。后端仍生成绑定视觉输入快照的透明文字层用于导出；导出按当前文字与样式重新渲染，不依赖手动排版按钮。

## 可重复的验证

页面任务与 CPU 蒙版计算可在“设置 → 性能与并发”中调节。同页操作保持有序；蒙版工作线程共享只读原图数据，计算完成后由页面任务保存结果与历史。颜色聚类使用输入绑定的随机种子（蒙版算法版本 4），串行与多线程应生成相同像素。使用 `bash scripts/test-backend.sh -q` 执行当前并发与蒙版回归；耗时报告需区分模型预热、蒙版计算、OCR 和修复，手写 OCR 样例需对照原图核查，旧识别结果不作为准确率标注。

```bash
PYTHONPATH=backend python scripts/compare_repair_masks.py \
  --output-dir tmp/repair-eval --filename 00000003.jpg --pages 1 \
  --all-regions --text-segmentation
PYTHONPATH=backend python scripts/compare_repair_masks.py \
  --output-dir tmp/repair-eval --render-only --device cuda --verify
python -m pytest backend/tests -q
```

对比脚本只读数据库与原图，结果写入单独输出目录，不替换工程净图；输出模型复核报告、蒙版和实图对比。蒙版面积及模型残留像素数是诊断指标，不是人工标注准确率。回归测试同时检查密集字形、气泡边缘保护、曲线分隔、阅读顺序、异形排版、手动修改保护、缓存与失败回退。
