# 常见问题

## 首次模型加载很慢

网页“安装推荐配置”会准备 RF-DETR、PaddleOCR-VL 1.6、LaMa 和 Pillow；也可按[版面检测说明](text-classification.md)和[本地 OCR 说明](local-ocr.md)单独安装。首次下载或模型加载需要等待，检查模型仓库的网络连通性与 `models/` 写入权限，通过 `./scripts/docker.sh logs -f backend` 查看真实进度。后续启动会复用缓存。

## 云端翻译仍返回原文

确认当前翻译 Provider 不是 `passthrough`，并在设置页成功连接 API、获取模型和保存密钥。地址、协议和模型写入 `config.yaml`，密钥写入 `.env`。

## Docker 无法使用 GPU

确认宿主机安装了 NVIDIA 驱动、Docker 和 NVIDIA Container Toolkit，再检查容器内 PyTorch/Paddle 的 CUDA 状态。没有 GPU 时，本地开发可以使用 CPU 依赖；当前默认 Compose 面向 NVIDIA GPU 镜像。

## 页面任务已完成但界面仍在加载

画布右上角“活动”卡片展示当次处理进度，可在推理时切换阅读其他页。成功或停止提示默认 15 秒自动关闭，也可手动关闭；失败提示保留供检查。若任务已结束但结果仍在同步，先查看后端日志。稳定复现时请提交脱敏后的任务 ID、浏览器版本、后台状态响应和复现步骤，不要附带 API Key 或原始漫画内容。

## PostgreSQL 连接或锁冲突

先通过 `./scripts/docker.sh ps` 检查 PostgreSQL 是否健康，确认私有密码未变、业务卷仍被正确挂载；不要删除数据库卷或恢复出厂设置。直接开发连接还需确认 URL 与进程环境中的 `PGPASSWORD`。

写入使用短事务、行锁和有限重试。持续锁冲突需要排查长事务与额外写入进程；未知提交结果不会自动重放。任务调度与模型锁仍为进程内状态，不支持多个后端实例并行接管同一队列。备份及数据库设置见[数据库配置](configuration.md)。

同项目历史提交会在打开事务前排队，不占用连接等待；与普通进度写入相比，历史提交允许更长的有限等锁时间。历史文件清理不应拿着项目锁扫描整个目录或读取大批 JSON。任务耗时中的 `db.project_queue_wait` 表示本地提交队列等待，`db.transaction_total` 表示实际数据库事务耗时。

同一任务的翻译、修复、进度与检查点写入也先按任务排队（`db.task_queue_wait`），不把模型推理串行化。检查点缓存读取不锁任务行；暂停、取消、重试和依赖状态变更则在短事务中锁行后判断当前状态，避免旧状态覆盖新状态。

## 翻译本次被拦截，但单页重新翻译成功

HTTP 成功不代表返回了译文。兼容接口可能以 `prohibited_content`、`content_filter`、`safety` 或拒绝内容块结束请求。错误提示描述的是本次响应，不代表该页面以后一定无法翻译。批量任务使用冻结的配置和上下文，单页新任务会读取当前配置与上下文，两次请求未必相同。不要忽略拦截标记、把空响应当成译文，或未经确认重复发送可能计费的请求。

批量修复与翻译在全部成功后才原子更新页面。若翻译失败但背景修复检查点已成功，净图暂不显示不等于修复没有执行；任务错误会说明已保留的阶段结果。确认后重试原任务可复用匹配的成功检查点；另建一个“重新翻译”任务不等于续跑原批次。旧任务的结果不能覆盖后来已编辑、重新检测或重新翻译的页面。

空白、仅包含不可见字符的原文不会发送。译文必须为非空文本并准确对应请求中的区域 ID，否则整次结果不覆盖已有译文。明确确认重试后，可以归档上次无效的空响应并仅请求缺失部分，不会永久重复回放同一空响应。密集页面中一个翻译分块失败后不再发出后续分块，已经发出的并行请求会收尾并保存可复用响应。

并行翻译和背景修复同时失败时，错误会同时说明两条分支。模型调用尚未开始就发生的进度保存失败，不应记成云端结果不确定；模型调用已经开始且结果状态保存失败时，会保守标记为不确定并要求确认后重试，不会自动重复可能计费的请求。
