# 开发指南

## 快速开始

```bash
./scripts/bootstrap.sh
# 先准备可连接的 PostgreSQL，并设置 MANGAFLOW_DATABASE_URL 和 PGPASSWORD。
# 数据库配置见 docs/configuration.md；默认 Compose 数据库不发布宿主机端口。
./scripts/dev.sh
```

前端地址为 `http://localhost:5173`，FastAPI 文档为 `http://localhost:8000/docs`。Docker 开发可使用：

```bash
./scripts/docker.sh up --build -d
./scripts/docker.sh logs -f
```

## 常用检查

```bash
./scripts/check.sh
./scripts/docker.sh config --quiet
```

后端测试通过 `backend/tests/conftest.py` 使用独立临时目录和 PostgreSQL 随机隔离 schema，不读取私有配置或本地项目数据。运行 `bash scripts/test-backend.sh -q` 会自动创建并销毁测试数据库容器；也可显式提供名称以 `mangaflow_test_` 开头的 `MANGAFLOW_TEST_POSTGRES_URL`。前端使用 Vitest、Testing Library、ESLint、TypeScript 和生产构建作为质量门禁；组件测试放在被测组件旁，并以用户可见行为和无障碍语义为主要断言。

前端构建同时检查未使用的本地变量和参数。删除内部参数时应同步更新所有调用方；路由装饰器、模型注册、独立推理进程和缓存键不能仅按文本引用数量判为死代码。历史归档、气泡素材和工作流检查点统一使用 `app.core.serialization.file_digest` 校验文件，保持已有内容寻址路径和校验值不变。测试中的 `model_engine` 已建表，不必再次执行 `create_all`。

## 新增 Provider

1. 在对应的 `backend/app/services/<stage>/` 中实现阶段协议。
2. 在 registry 中注册名称、设备、依赖和说明。
3. 为 Provider 添加配置校验和缺少依赖时的明确错误。
4. 更新 `config.example.yaml`、设置页候选说明和文档。
5. 添加不依赖真实云端密钥的测试。

## 新增前端业务

单一业务域放在 `frontend/src/features/<feature>/`，路由页面留在 `pages/` 负责数据编排。可复用表单、Dialog 和加载状态留在 `components/`。体积较大的路由使用 `React.lazy`，并使用直接路径导入以保持分包边界。

## CI

GitHub Actions 在 Python 3.11/3.12 上运行 Ruff 和 Pytest，在 Node 20 上运行 ESLint、Vitest 与生产构建，并校验公开配置模板、应用版本和 Docker Compose。依赖升级由维护者按需评估，不自动创建升级 Pull Request。

## 批量性能改进

当前仅支持 PostgreSQL 18 与 psycopg 3，数据库使用独立 Docker 持久卷。阶段检查点、原文框修复与翻译并行、CTD CUDA 和工作文件回收继续按配置启用。下文模型性能数字是历史专项验收记录，不代表每次运行的耗时。

任务执行尝试的耗时写入 `task_execution_runs`，不会随 `/api/execution` 的最近 100 条内存采样淘汰。通过 `GET /api/tasks/{task_id}/timings?limit=50&offset=0` 查询；任务列表也支持 `limit`（1–500）和 `offset`，默认响应仍兼容原接口。旧任务没有记录时返回空列表，不推算不存在的阶段耗时。

每次执行记录排队时间、墙钟时间、完成状态及阶段/组件累计时间。组件包括本地模型等待与推理、CTD 解码与推理、CPU 工作、云端翻译等待与请求、数据库重试和历史文件归档。阶段完成后保存快照，进程中断的未结束尝试在启动恢复时标记为 `INTERRUPTED`。耗时记录不保存原文、译文、请求内容或密钥。诊断保存失败会记录日志，不将已成功的处理任务改判失败。

组件时间是包含子操作的累计值：翻译可能包含补 OCR，多个 CPU 操作可能重叠，数据库事务时间也包含重试等待。**不能相加当作任务或批次墙钟时间。** 诊断表暂不自动清理，随对应任务删除级联删除；历史任务的最终性能比较需要另行导出固定批次的完整样本。

任务撤销记录采用“读取快照 → 释放事务 → 归档文件 → 短事务核验并保存”。文件哈希和复制不占数据库写锁；核验失败重新取快照，写冲突只重试数据库事务，不重复归档或模型推理。文本框、蒙版、撤销重做，以及页面导入、删除、重置和排序使用相同的锁外准备原则；发布时核验页面版本或图片列表，冲突返回 409，不覆盖更新后的内容。重置或删除页面不再在提交后递归删除页面目录，以免与撤销或新任务竞态；数据库引用决定当前显示内容，旧文件供历史恢复使用。

翻译阶段也将输入、语言和版本先取成快照，在云端请求前释放读事务。返回结果使用短事务保存，锁冲突只重试结果写入，不重新请求翻译。输入已删除或编辑时整份结果拒绝覆盖，避免部分译文与新原文混合；没有补 OCR 的翻译失败不会清空之前发布的译图。默认旧流水线仍只有上述单阶段保护；下面的检查点路径才提供跨阶段整体发布保护。

CTD 保持相同模型、预处理、概率缓存键和蒙版阈值。新增最多 64 MiB 的只读源图 LRU 缓存，局部窗口复用解码和内容哈希；同一模型的冷启动和同一磁盘概率缓存缺失时合并并发请求。缓存按文件签名失效，读取过程中源图变化会报错，不发布混合版本结果。

可用 `PYTHONPATH=backend .venv/bin/python scripts/benchmark_segmentation_cache.py <原图路径>` 进行只读微基准，验证解码像素与缓存键一致并比较输入准备耗时。该脚本不加载模型、不访问云端，也不修改项目数据；输出不是整条流水线的提速倍数。

数据库使用 Alembic 版本化迁移。只读事务不会误判为未提交写入，事务重试仅覆盖明确可重试的锁超时、序列化失败和死锁，不重试提交结果未知的连接故障。阶段副本采用连接私有的临时表，仅搜索 `pg_temp`；提交、回滚、并行分支及异常关闭均由隔离测试覆盖。

### 阶段检查点与原子发布

`MANGAFLOW_CHECKPOINT_PIPELINE_ENABLED=true` 将整页重新检测、单独 OCR/翻译/修复/排版、选区操作及整页翻译修复任务接入检查点流程。绑定单个待删除区域的检测任务仍走兼容路径，避免替换区域时级联删除任务自身。开关的源码默认值仍为关闭，本机经过验收的私有 `.env` 已显式开启。`MANGAFLOW_PARALLEL_REPAIR_TRANSLATION=true` 另行允许整页原文框修复与翻译并行；使用译文框修复时仍按依赖串行执行，并在生成蒙版前初始化译文角度。

流程先对符合翻译条件的空白原文补 OCR，再执行翻译和蒙版/修复，最后合并字段、排版并发布。各阶段使用私有 ORM 工作副本及独立文件目录，不写正式页面。所有必需阶段成功、文件校验通过，且页面/区域版本和项目翻译配置仍匹配时，才在短事务内同时更新页面、区域、任务和一条撤销记录。失败、取消或过期执行不能覆盖原来的净图和译图；未发布的阶段图片不能从 `/media` 访问。

`task_workflows` 保存冻结输入及配置，`stage_checkpoints` 保存阶段差量、资源摘要、执行代次和状态。重试复用匹配的成功结果；上页后来完成不会使已保存的译文失效。暂停在阶段边界生效，已发出的调用先排空并保存结果；恢复不重复成功阶段。关闭新任务的检查点开关后，已有检查点任务仍沿原路径续跑，避免丢弃已付费结果。

检查点路径对结果不确定的云端请求不做隐式重发。明确的 HTTP 429 仍遵守限流退避；其他请求失败或进程中断记为需确认的状态，普通重试/恢复返回 409。确认端点参数为 `allow_unknown_cloud_retry=true`，仅供明确授权的 API 调用使用。旧“项目任务”弹窗及其暂停、恢复、重试入口已移除；画布右上角的“活动”卡片允许停止对应的在途任务，但不会自动重试或重发云端请求。成功响应落库失败同样按保守策略处理，不假定服务端没有处理请求。

隔离用例验证真实线程重叠、失败分支单独重跑、暂停续跑、旧页面保护、发布事务回滚、旧代次拒绝、源版本冲突、撤销/重做和阶段资源访问限制。原生 OCR 按裁剪保存成功结果，云端按已验证的成功响应保存结果，重试仅补缺失项。未知云端结果仍须明确确认，不能保证请求崩溃窗口内绝不重复计费。工作文件回收有七天保留期、扫描/删除数量和时间预算，并保护已发布页面、修订、撤销重做、未发布成功结果及未知请求证据。

### 批次上下文与任务操作

迁移 `20261018_05` 新增私有批次快照和依赖字段，保留现有任务及检查点。快照固定提交时的模型配置、源/目标语言、术语上下文、修复配置与上页内容；私有加密配置不进入任务 API 的 `payload`。后续设置修改仅影响新批次，发布仍核验页面与区域版本。

项目“翻译上下文”可选两种模式。默认 `snapshot` 让各页使用提交时快照并发翻译；`previous_page` 依赖同批次紧邻前页的翻译检查点，前页修复尚未完成时即可继续。前页不在批次内时使用其提交时快照。等待依赖不占页面名额，完成事件仅唤醒关联任务；30 秒超时只用于恢复外部状态变化。前页暂停、失败或依赖丢失会明确显示，不静默换成旧译文。

请求中的命名 Provider 仅作用于请求的起始阶段。比如 `translation → rendering` 选择特定翻译模型时，修复与排版使用各自的默认模型；翻译前补 OCR 也使用 OCR 默认模型。旧流水线和检查点路径采用相同规则，避免把翻译模型名误当成修复器名称。

画布右上角“活动”卡片只展示当次操作，最多显示 5 个未结束任务；不展示服务器返回的历史终态任务。每项显示阶段、页码、文件名、进度及安全停止按钮；公开 payload 提供 provider 时也显示它。监控保留所有在途任务的页面锁，卡片切换或隐藏不影响后台工作。恢复状态时分批读取有上限的任务摘要，再按 ID 查询活动状态；全部恢复分批结束后才显示完成汇总，不会只计算前 5 个。成功或停止提示可手动关闭，默认 15 秒自动关闭；失败提示保留到手动关闭。旧提示的定时器、关闭动作和迟到响应不会关闭或重现下一次操作的提示。

`GET /api/projects/{project_id}/batches/{batch_id}` 继续供 API 调用，按提交时总页数统计，仅 `COMPLETED` 计入完成进度；失败、取消和已删除的任务另列。暂停在安全边界排空在途工作；排队任务可立即停止等待并恢复。同一页面保持有序，待处理页面在项目间轮转；交互请求最多连续优先三次，然后给批量队列一次机会。

任务进度列表跟随编辑器加载；检查点批次的中间状态不会触发整页区域重复拉取。

### 编辑器命令与已移除入口

单页处理命令仅包含重新检测（检测后 OCR）、重新修复和重新翻译；所选区域仅包含重新 OCR、重新修复和重新翻译。独立的重新排版按钮、快捷键和手动命令分支已移除，旧快捷键设置会在加载时过滤失效项，保留其余自定义绑定。旧移动端流程栏、批量框对齐、复制/拆分及重复显隐前端分支、无路由的质量复查页、旧历史预览函数和无调用方的请求/加载样式封装也已清理。图层显隐仍通过属性更新生效。

排版、渲染和字体适配仍是有效的自动处理阶段：修复、翻译、编辑后预览及导出依赖它们，不能随按钮一起删除。后端通用处理、区域复制/拆分、任务控制等公共接口保留兼容用途，不再由已移除的前端入口调用。撤销/重做保留历史排版操作的显示标签，不修改已有项目历史。

全项目清理还移除了旧横排/竖排与多边形缩放算法、废弃的气泡内接框算法、旧 Paddle 检测输入封装、无调用方的请求结构、几何工具和全页历史归档封装。前端不再经过恒等的 `shapeText` 封装及其不可达裁剪分支，后端也不再接收无效的 `shape_masks` 参数。实际流程只使用当前的 ink-bounds 排版、RF-DETR 检测和短事务历史快照；PaddleOCR 的识字结果解析保持有效。性能测试改为直接验证当前 ink-bounds 和画布路径，不再只测试旧换行辅助函数或恒等封装。配置示例和使用文档不再提供已移除的手动排版快捷键或操作步骤。

Python 安装包仅包含 `app` 命名空间，不打包后端测试；数据库迁移必须随包保留，CI 会检查实际 wheel 内容。发布打包应使用干净源码树，避免 setuptools 的旧 `build/lib` 缓存重新带入已删除模块；构建目录和 egg-info 也排除在 Docker 上下文外。

### 资源窗口与可选 CTD CUDA

页面、CPU 和按接口/密钥/模型隔离的云端预算分别观察完成工作量。自适应增加需要队列有等待、至少 30 秒和 8 项同类样本；试增一路后须取得至少 10% 吞吐提升，且归一化 P95 增长不超过 20%，否则回退并冷却 60 秒。不同阶段不混合验证，普通云端/校验失败不按本地 CPU 内存不足处理。云端翻译现也参与自身窗口学习，RPM 和上游退避仍约束每次请求。本地模型暂仍共享单路资源门禁。

可选 `MANGAFLOW_SEGMENTATION_BACKEND=onnx_cuda` 使用同一 SHA-256 权重、1024 输入、RGB 预处理及 FP32，关闭 TF32。Docker 安装与当前 CUDA 12/cuDNN 9 匹配的 ORT，并注册已有 NVIDIA wheel 库目录。显存不足、缺依赖或运行失败会记录原因并回退 OpenCV；CUDA 与 OpenCV 概率缓存独立，回退结果不会写入 CUDA 缓存。修复阈值和用户手工蒙版不变，CUDA 设置纳入冻结策略。MangaOCR 微批次与 CTD 都预留至少 2 GiB 或总显存 15% 的余量。

`scripts/benchmark_ctd_backends.py` 在源数据和模型只读挂载的隔离进程中比较整页及局部窗口、生成蒙版和字形连通分量，输出逐页耗时与质量门禁。它不调用翻译接口，结果不能代表整本翻译/修复的耗时。源码默认仍使用 OpenCV；本机在下述完整修复和整批验收通过后显式启用 CUDA。

2026-10-18 V100 16 GiB 实测：24 页（16 页包含已检测区域，共 217 区域、41 个局部窗口），CTD 累计 OpenCV 425.519 秒、CUDA 3.709 秒；P95 分别 44.920 秒与 0.331 秒。所有生成蒙版逐像素一致，未丢失字形连通分量，源图摘要保持一致。包含空白/未检测页，暂未覆盖全部气泡约束、手工蒙版、重复冷启动或完整修复质量，因此还不能作为整条流水线或整批性能的完成证明。ORT 1.20.2、Torch 2.6.0+cu126、cuDNN 9.5.1，TF32 关闭；报告保存于隔离验收目录 `ctd-parity-24.json`。

最终固定 24 页完整 mask＋LaMa 修复验收：冷缓存从 760.99 秒降至 73.84 秒，暖缓存从 89.36 秒降至 51.66 秒。自动 mask 最大差异为并集的 0.02677%，低于 0.1% 门槛，无完整字形连通分量丢失；手工 mask 语义、局部未选中区域及 mask 外像素检查通过。这里的冷暖指应用及模型缓存，不是操作系统页缓存。两个 CTD Session 的吞吐虽提升约 21.7%，P95 却增长约 128%，未通过延迟门禁，因此实际 GPU 推理保持单路。

原批次 337 页的独立副本仅进行一次真实付费翻译＋修复：墙钟 1165.67 秒（约 19 分 26 秒），336 页成功、1 页云端结果未知，数据库冲突失败为零。该未知请求未自动重发。峰值采样页面并发 4、CPU 工作 5、本地模型 1；源项目指纹和全部测试输入素材校验一致。测试使用 Docker 命名数据卷，不同于原 Windows bind mount，且历史批次有 21 页失败，不能据此声称严格同条件的整批加速倍数。整本不含真实手工 mask/手动字体，相关语义由固定集及功能回归另行覆盖。

导出补渲染使用普通快照数据进入有界 CPU 池，在线程内建立私有适配器。各次渲染使用独立 UUID 文件名，短事务重新核验页面版本后发布缓存；计算期间有新编辑时返回 409，不覆盖它，也不额外占用撤销步骤。归档及 ZIP 打包均不持有应用写锁，公开图片地址和项目包回导已回归验证。过期且无引用的 UUID 导出图由相同的保留期/限量回收机制处理，旧格式和用户文件不会按该规则删除。

### 全流程并行、文字去重与黑白配色复核（2026-10-18）

从 337 张原图重新执行检测、MangaOCR、真实翻译接口、蒙版、LaMa、渲染和发布，最新一轮墙钟为 2003.83 秒，上一轮为 2018.71 秒，差异仅约 0.74%，不能宣称显著整批提速。最新一轮 330 页成功、7 页翻译失败：4 页接口返回 `prohibited_content`，2 页漏回部分区域 ID，1 页为空且上游原因未知。未知计费结果不自动重发；明确确认重试后，只请求缺失 ID。API 返回的可重放内容仅保存于私有工作流缓存，不通过媒体接口公开。

检测完成后，整页 OCR 结果作为共同输入，翻译与原文框修复可以并行；译文框修复仍串行。IoU 仅辅助高重叠候选的字形证据验证，不代替完整包含关系、气泡/分镜归属和连通分量裁切检查。密集说明页另外利用确实为空的段落间隙分解大框与其小框的原始字形并集，保留大框独有文字；不膨胀修复 mask，不按矩形重叠直接删除文字。

已验证的横竖排长段落为本地 MangaOCR 提供有界行列裁图，合并完成后才保存该区域；用户修改原文框后不复用旧裁图。子裁图共享行列间隙，避免常规 OCR 扩边带入相邻行。这个处理消除了实测长段落触及单次生成上限的问题，但不保证细小密集字形逐字正确。

自动配色仅选择黑/白文字和相反颜色描边，采样原始字形及实际修复背景；结果写入现有颜色字段，编辑器与导出使用相同值。用户明确设置颜色或描边后转为手动样式，撤销重做恢复该状态。自动描边按最终字号计算，排版先预留固定的最大描边空间，避免重复导出时字号/描边逐次漂移。

LaMa 的读图、裁图、合成和 PNG 保存已移出全局推理锁，只有模型加载/推理/回退位于同一安全临界区，锁顺序始终为全局模型锁→Provider 锁。4 张真实原图和保存蒙版、4 线程每轮 8 次修复的三轮本地测试，中位耗时 3.93→1.39 秒；前后像素最大差值 1，发生比例低于百万分之一。该局部测试不是整批翻译速度保证，实际 GPU 推理仍单路。

真实回归夹具与专项测试：`test_dense_prose.py`、`test_hybrid_iou_dedup.py`、`test_native_prose_ocr.py`、`test_inference_lock_scope.py`、`test_translation_response_compat.py`、`test_full_pipeline_parallel.py`、`test_text_paint.py`。接口内容限制不通过程序绕过；OCR 误读、漏检测和模糊交叠仍需要质量复核，不能把文件安全检查或低 IoU 当作识别准确性的证明。
